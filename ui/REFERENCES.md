
# UI Design References

This document defines the visual references used when designing the application.

These references are inspiration only.

Do not copy proprietary branding, logos, assets, illustrations, or exact layouts.

---

## 1. Primary Style

### Modern SaaS Product UI

Primary characteristics:

- minimal
- professional
- clean
- strong typography
- restrained colors
- subtle surfaces
- generous whitespace
- clear actions
- high information clarity

This is the default visual direction.

---

## 2. Linear-Inspired Principles

Useful principles:

- compact but readable navigation
- strong typography
- subtle borders
- restrained colors
- excellent spacing
- dense but organized information
- keyboard-friendly interaction
- subtle animation

Do not copy Linear branding or exact UI.

---

## 3. Vercel-Inspired Principles

Useful for:

- minimal visual language
- monochrome hierarchy
- clean layouts
- strong typography
- subtle borders
- restrained surfaces

Do not blindly copy the black-and-white visual identity.

Adapt the principles to the application.

---

## 4. Stripe-Inspired Principles

Useful for:

- professional forms
- strong information hierarchy
- clear CTA hierarchy
- polished documentation-like layouts
- high-quality spacing

Do not copy Stripe branding.

---

## 5. GitHub-Inspired Principles

Useful for:

- data-heavy interfaces
- tables
- filters
- navigation
- developer-oriented workflows

Prefer readability over excessive density.

---

## 6. shadcn/ui-Inspired Principles

Useful for:

- buttons
- forms
- cards
- dialogs
- dropdowns
- tables
- typography
- semantic color tokens

The application may use Tailwind patterns inspired by this philosophy.

Do not blindly copy component implementations.

---

## 7. Visual Characteristics

### Background

Subtle neutral background.

### Surface

Clear surface differentiation.

### Border

Thin and subtle.

### Radius

Moderate.

### Shadow

Subtle.

### Typography

Strong hierarchy with restrained weights.

### Accent

One primary accent color plus semantic status colors.

---

## 8. Things To Avoid

Avoid:

- excessive gradients
- excessive glassmorphism
- excessive shadows
- huge rounded cards
- rainbow color palettes
- too many font sizes
- excessive animations
- emoji as icons
- unnecessary decorative elements
- visual noise

---

## 9. Template Selection

When redesigning a page, first classify it.

### Dashboard

Use:

- compact header
- KPI cards
- charts where useful
- clear sections
- data hierarchy

### CRUD / Management

Use:

- page header
- primary action
- filters
- search
- table/list
- pagination

### Form

Use:

- narrow content width
- grouped sections
- labels
- descriptions
- validation
- clear action area

### Landing / Marketing

Use:

- stronger typography
- hero
- visual hierarchy
- feature sections
- CTA
- restrained decorative elements

### Settings

Use:

- sidebar or tabs
- grouped settings
- clear labels
- save actions
- destructive actions separated visually

### Detail Page

Use:

- breadcrumb when useful
- title
- metadata
- primary actions
- content sections
- related information

---

## 10. Reference Rule

When a screenshot or reference is provided:

Analyze:

- layout
- spacing
- typography
- component proportions
- surface hierarchy
- border treatment
- color relationships
- interaction patterns

Do not reproduce the exact design.

Translate visual principles into the application's own design system.

---

## 11. Final Principle

References answer:

"What kind of quality should this UI have?"

They do not answer:

"What exact pixels should we copy?"

The application's content, UX, and brand always take priority.
